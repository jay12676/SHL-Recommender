# Conversational SHL Assessment Recommender — Design

Date: 2026-06-30
Status: Approved (data validated against the live catalog + 10 traces)

## 1. Problem & success criteria

Build a stateless conversational agent that takes a user from a vague hiring intent
to a grounded shortlist of SHL **Individual Test Solutions**, exposed as a FastAPI
service (`GET /health`, `POST /chat`). It must clarify, recommend (1–10), refine,
compare, and refuse out-of-scope requests. Every returned URL must come from the
scraped catalog.

Scored on: (a) **hard evals** — schema compliance, catalog-only items, ≤8 turns;
(b) **Mean Recall@10** on final shortlists; (c) **behavior-probe pass-rate**
(refuses off-topic, no recommend on turn-1 vague query, honors edits, low
hallucination).

## 2. Data

- Source: `shl_product_catalog.json` (377 individual test solutions). Fields:
  `entity_id, name, link, job_levels, languages, duration, remote, adaptive,
  description, keys`. Raw JSON contains unescaped control chars → parse with
  `strict=False`, always UTF-8.
- `test_type` is **derived from `keys`** using the 8 SHL codes:
  `A`=Ability & Aptitude, `B`=Biodata & Situational Judgment, `C`=Competencies,
  `D`=Development & 360, `E`=Assessment Exercises, `K`=Knowledge & Skills,
  `P`=Personality & Behavior, `S`=Simulations. Multiple keys → comma-joined
  (e.g. `"K,S"`).
- A build step normalizes raw → `data/catalog.json`: stable `id`, `name`, `url`
  (from `link`), `test_type`, plus a precomputed `search_text`
  (`name + description + keys + job_levels`) for retrieval.

## 3. API contract (non-negotiable schema)

Request: `{ "messages": [ {"role": "user"|"assistant", "content": str}, ... ] }`

Response:
```json
{ "reply": str,
  "recommendations": [ {"name": str, "url": str, "test_type": str}, ... ],
  "end_of_conversation": bool }
```
- `recommendations` is `[]` (empty array) while clarifying or refusing; 1–10 items
  when committing to a shortlist. (PDF says "EMPTY"; trace `.md` renderings show
  `null` but the PDF JSON contract is authoritative.)
- `name`, `url`, `test_type` are always copied from the catalog by `id` — never
  generated by the LLM. This is the core anti-hallucination guarantee.

## 4. Architecture — stateless, two-call agent

Every `POST /chat` rebuilds all state from the full message history; the server
stores nothing.

```
request → validate → UNDERSTAND (Groq, JSON) → route
  ├─ refuse   → reply, recommendations=[]
  ├─ clarify  → reply(question), recommendations=[]
  └─ recommend→ RETRIEVE candidates → COMPOSE (Groq, JSON) → map ids→catalog
                → post-filter (honor explicit excludes) → recommendations(1–10)
```

- **Understand call** (input: conversation) → JSON:
  `{action: clarify|recommend|refuse, in_scope, injection_detected,
    expanded_query, test_type_hints[], job_level_hint,
    must_include[], must_exclude[], clarifying_question}`.
  `expanded_query` rewrites the whole conversation into a retrieval query with
  role + skills + synonyms (e.g. "works with stakeholders" → "communication
  influencing interpersonal"). `must_include`/`must_exclude` capture explicit
  edits from the latest user message.
- **Retrieve** (only for `recommend`): hybrid over `data/catalog.json`.
- **Compose call** (input: conversation + candidate list) → JSON:
  `{reply, selected_ids[], end_of_conversation}`. The reply also carries grounded
  comparison text when the user asked to compare. Selection is restricted to
  candidate ids; the server maps ids → catalog records.

We collapse "compare" and "refine" into the `recommend` path: both end in a
maintained/updated shortlist plus an explanatory reply. Fewer branches → more
robust to non-deterministic conversation.

## 5. Retrieval

- **BM25** (`rank_bm25`) over `search_text` — strong on exact skills (Java, SQL).
- **Optional embeddings** (`sentence-transformers` all-MiniLM-L6-v2, brute-force
  cosine in numpy — catalog is tiny, no FAISS) — catches semantic matches.
  Fused with **Reciprocal Rank Fusion**. Controlled by `USE_EMBEDDINGS`; if the
  model/torch is unavailable the system **degrades gracefully to BM25-only**.
- `test_type_hints` / `job_level_hint` apply as **soft boosts**, never hard
  filters (protects recall).
- A small curated **core set** (OPQ32r, Verify G+, GSA, Graduate Scenarios) is
  always injected into the candidate pool — the traces show these recur as default
  personality/cognitive/SJT components. They are *available* to the selector, not
  auto-recommended.
- Returns ~30 candidates to the compose step.

## 6. Agent behavior guards (deterministic, not LLM-trusted)

- **No recommend on turn-1 vague query:** understand returns `clarify` unless the
  query has a role + at least one of {skills, level, context}. Specific turn-1
  queries (full JD) may recommend immediately.
- **Clarify budget:** at most 2 clarifying turns. If the assistant has already
  asked ≥2 questions (counted from history) the router is forced to `recommend`,
  so we never exhaust the 8-turn cap clarifying.
- **Honor edits:** `must_exclude` items are filtered out of the final
  recommendations even if the LLM re-includes them; `must_include` test types are
  ensured present. Guarantees the "honors edits" probe deterministically.
- **Scope/injection:** off-topic, legal, general hiring advice, and
  prompt-injection → `refuse`, empty recommendations. Detected in the understand
  call and reinforced by a keyword/heuristic backstop.
- **URL grounding:** recommendations built only from catalog by id; any id the LLM
  invents that is not in the candidate set is dropped.
- **LLM-failure fallback:** on Groq error/timeout, degrade to BM25 top-K with a
  generic reply so the response is always schema-valid (never 500 the evaluator).
- **Turn cap / latency:** ≤2 Groq calls per turn (~3–6 s), well inside the 30 s
  timeout; clarify/refuse use a single call.

## 7. Stack

FastAPI + Pydantic v2 (enforces the non-negotiable schema), Groq SDK
(`llama-3.3-70b-versatile`, free tier, JSON mode), `rank-bm25`, numpy, optional
`sentence-transformers`. Core `requirements.txt` is deploy-light (BM25 only);
embeddings are an optional extra.

## 8. Evaluation

- **Replay harness** (`eval/harness.py`): an LLM-simulated user (Groq) driven by
  each trace's persona/facts runs a real multi-turn conversation against an
  in-process `/chat`, then computes **Mean Recall@10** vs the trace's expected
  shortlist (parsed from `C1..C10.md`).
- **Behavior probes** (`eval/probes.py`): binary assertions — refuses off-topic,
  no recommend on turn-1 vague, honors a drop/add edit, every URL ∈ catalog,
  ≤8 turns, schema valid every turn.
- **Unit tests** (`pytest`): schema validation, catalog loader + test_type
  mapping, retrieval sanity (Java query surfaces Java tests), guard logic
  (exclude filtering, clarify budget), URL grounding.

## 10. Out of scope (YAGNI)

No persistence/DB, no auth, no streaming, no multi-language UI, no Job Solutions
(individual test solutions only), no FAISS (catalog too small to need it).
